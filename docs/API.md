# API

Interactive documentation is generated by FastAPI at `/docs`; the schema is at
`/openapi.json`. This page covers the contracts that matter.

## Honesty contracts

Enforced in code and covered by tests in `backend/tests/test_api.py`.

| Contract | Behaviour |
|---|---|
| No invented probability | `risk.probability` is `null` unless a calibrated supervised model produced it. Under `hybrid_indicator` mode it is always `null`. |
| No invented position | A well with no surveyed position has `latitude: null`, and `/nearby` returns **409** rather than assuming a location. |
| No silently reduced evidence | Every analogue match reports `dimensions_used` and `dimensions_unavailable`; weights are renormalised over what was computable. |
| Absence is explicit | A well without telemetry returns **409**, not `[]` — an empty array reads as "all quiet". |
| Untrained is not zero | `/api/models/{name}` returns **404** saying the model has not been trained, never placeholder metrics. |
| Retrieval is not authorship | `/api/documents/search` returns source passages with page citations. No endpoint generates prose about a well, and no LLM writes a risk assessment or a mitigation. |
| Partial index is disclosed | Search reports how many passages were searched against how many are stored, so an incomplete index cannot pass as a complete search. |

### `/api/documents/search`

Returns **passages, not answers**. Each result is the OCR'd text of a stored chunk with
the document title and page number it came from, so the engineer reads the source and the
citation says where to find it. Nothing here summarises or paraphrases.

The response carries a `provenance` object describing what was actually searched:

```json
{
  "results": [
    {
      "chunk_id": 41,
      "document_title": "60_15_9_17_Completion_report_and_log",
      "well_id": 7, "well_name": "15/9-17", "page_number": 17,
      "similarity": 0.7514,
      "text": "…the shale/claystone is mainly medium to dark grey, firm, subfissile…"
    }
  ],
  "provenance": {
    "passages_searched": 75, "passages_indexed": 75, "passages_total": 75,
    "model": "sentence-transformers/all-MiniLM-L6-v2",
    "similarity_metric": "cosine", "min_similarity": 0.25
  }
}
```

`passages_indexed` below `passages_total` adds a `note` naming how many stored passages
have no embedding and were therefore not searched — a partial index must not read as a
complete search.

Similarity is raw cosine in `[-1, 1]`, and results below `min_similarity` are dropped
rather than returned as the least-bad passage. An **empty `results` list means no passage
cleared the threshold**, which is a real absence.

Returns **503**, naming the command that builds the index, when no passage has an
embedding yet — never an empty list, which would read as "nothing in the reports matches".

## Replay and live telemetry

| Method | Path |
|---|---|
| POST | `/api/replay/{id}/start?speed=` |
| POST | `/api/replay/{id}/pause`, `/resume`, `/stop` |
| POST | `/api/replay/{id}/speed?speed=`, `/seek?index=` |
| GET | `/api/replay/{id}` |
| WS | `/ws/telemetry/{well_id}` |

Replay state is owned by the server, so multiple viewers stay consistent. The socket sends
`connected`, then one `sample` message per row, then `finished`. Every sample is a stored
database row with its original timestamp — nothing is synthesised.

```json
{
  "event": "sample",
  "state": {
    "status": "running", "current_index": 42, "total_samples": 59806,
    "current_timestamp": "2016-09-30T10:11:00", "current_depth_m": 1204.5,
    "source": "Volve WITSML replay"
  },
  "sample": {
    "recorded_at": "2016-09-30T10:11:00", "bit_depth_m": 1204.5,
    "channels": {"standpipe_pressure_bar": 118.4, "hookload_kn": 812.3},
    "operations_active": true
  }
}
```

## Risk response shape

```json
{
  "mode": "hybrid_indicator",
  "score": 0.6896,
  "risk_level": "HIGH",
  "probability": null,
  "components": [
    {
      "name": "anomaly", "value": 0.82, "weight": 0.4,
      "explanation": "telemetry anomaly score 0.820 (unsupervised; not a probability)"
    }
  ],
  "historical_evidence": [
    {
      "well_name": "NO 15/9-F-7", "similarity_score": 0.8967,
      "depth_start_m": 866.0, "distance_from_bit_m": 16.0,
      "description": "release spear and pooh with RT and 5 1/2 DP",
      "depth_source": "telemetry_time_join", "mitigations": []
    }
  ],
  "narrative": "HIGH indicator for NO 15/9-F-4 at 850 m MD...",
  "notes": [
    "only 0 categorised historical events exist (threshold 200), so risk is reported as a historical indicator rather than a supervised prediction, and no probability is produced"
  ]
}
```

`depth_source` deserves attention: `telemetry_time_join` means the source record carried no
usable depth and it was recovered by matching the event timestamp against telemetry. That
distinction stays visible to the engineer reviewing the evidence.

## Errors

Errors are sanitised; internals never reach the client. Database failures return **503**
with a message stating that no data was returned and nothing shown is estimated.
